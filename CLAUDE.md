# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Lexoria — a Wordscapes-like English word puzzle game (letter wheel + crossword grid), built as a pure vanilla JS/ES-modules web app with no framework, no bundler, and no backend (Phase 1; Capacitor embedding is Phase 2). UI text is Traditional Chinese; word definitions are Traditional Chinese (ECDICT, primary) plus English (WordNet, secondary).

The two design documents are the source of truth and code comments cite their sections (e.g. `§10`):

- [docs/word-puzzle-game-design.md](docs/word-puzzle-game-design.md) — gameplay rules, architecture decisions, level-generator algorithm, economy values, licensing, the Phase 1 acceptance checklist (§17), and an explicit YAGNI list (§16) of things deliberately not built. Consult §16 before adding any new system.
- [docs/word-puzzle-ui-screens.md](docs/word-puzzle-ui-screens.md) — screen inventory, overlay stacking rules, UI copy table, color palette.

## Commands

Every command lives in [package.json](package.json) `scripts` — [mise.toml](mise.toml) is `[tools]` only (bun and prek pinned, uv floating on `latest`, nothing else). Don't add mise tasks that wrap `bun run`; that duplication was removed on 2026-07-29.

`mise.toml` is the **only** place *tool* versions are pinned, locally and in CI — pr-check.yml uses `jdx/mise-action`, so bumping bun/uv/prek is one edit. (Hook versions are the one exception and stay that way: `.pre-commit-config.yaml`'s `rev:` pins are prek's, not mise's.) What this replaced on 2026-07-29 was `oven-sh/setup-bun` with `bun-version: latest` — **there was never a `.bun-version` file**; CI simply floated on whatever bun shipped that morning while `mise.toml` pinned 1.3.14, so a bun regression could turn a PR red with nothing reproducible locally. CI also needs prek, and mise-action installs it from the same file anyway. If mise-action is ever dropped, `.bun-version` (one line, no comments — `bun-version-file` reads the whole file) is how CI would get the pinned version back; mise *can* read it too, but idiomatic version files are off by default (`idiomatic_version_file_enable_tools` is `[]`), so single-sourcing it that way costs a `[settings]` opt-in in the very file you were trying to empty.

```sh
bun run test        # unit tests (bun test)
bun run lint        # Biome lint + format check (biome.json), warnings included; bun run fix auto-fixes
bun run check       # lint + test — the local hook prek runs, alongside the upstream file checks
bun run serve       # dev server on :8080 (ES modules need http; opening index.html from file:// won't work)
bun run fetch-data  # download generator inputs → tools/data/ (ENABLE word list; wordfreq+WordNet via uv/python)
bun run gen         # regenerate data/levels/ (requires fetch-data first)
```

`lint` carries **`--error-on-warnings`**, and that flag is load-bearing: `biome check` exits 0 on warnings by default, so without it every rule set to `"warn"` in biome.json is a rule that prints and lets the commit through. Five of them are (`noExcessiveCognitiveComplexity`, `noAccumulatingSpread`, `noAwaitInLoops`, `useTopLevelRegex`, `noProcessGlobal`) — measured 2026-07-29 with a throwaway top-level-regex violation: `biome check` exit 0 + "Found 1 warning", `biome check --error-on-warnings` exit 1. Same failure family as the prek catches below, one layer down: **a check can be present, green, and doing nothing.** The tree was already warning-clean when the flag went on, so it cost nothing; the price is that `noExcessiveCognitiveComplexity` now blocks commits (`game.js`'s `createGame` sits exactly on the limit of 15 — it carried a `biome-ignore` until 2026-07-30, when deleting one always-true condition bought the point back; note that `--error-on-warnings` also fails on a `biome-ignore` that stops being needed, so the suppression had to go with it). If a warn-level rule ever becomes more annoying than useful, set it to `"off"` and say why — don't drop the flag, that silently re-disarms the other four.

Checks run through [prek](https://prek.j178.dev/) (a Rust pre-commit, pinned in `mise.toml`): run `prek install` once per clone to write `.git/hooks/pre-commit`; `prek run --all-files` runs everything by hand, `git commit --no-verify` skips it. [.pre-commit-config.yaml](.pre-commit-config.yaml) holds the upstream `pre-commit-hooks` file checks (large files, case/Windows-name conflicts, merge conflicts, symlinks, YAML syntax, private keys, end-of-file newlines, mixed line endings, trailing whitespace — the file keeps them in `id` alphabetical order, and this list mirrors it), the `gitleaks` secret scanner, and one `local`/`system` hook running `bun run check`. **CI runs `prek run --all-files`, not `bun run check`** — the point is that hooks which can't be a package.json script (whitespace, secret scanning, YAML lint, …) get enforced in CI the moment they're added to that file, with no workflow edit and no second list to keep in sync. Adding a hook there is the whole change; pr-check.yml should stay untouched — with three catches, all of the same family: **a hook can be present, green, and doing nothing.** First, `prek run` only runs the `pre-commit` stage, so a hook copied in with `stages: [pre-push]` (some upstream secret scanners ship that way) is silently skipped in CI. Leave hooks on the default stage. Second, **`gitleaks` is a commit-time gate only, not a CI one**: its upstream entry is `gitleaks git --pre-commit --redact --staged --verbose`, and under `--all-files` nothing is staged, so in CI it scans an empty diff and always passes (measured 2026-07-29: a `ghp_…` token fails the hook when staged, passes under `prek run --all-files`). Don't read a green PR Check as "no secrets". Making it real means `gitleaks dir`, which needs an allowlist config — a bare `gitleaks dir .` walks `node_modules` + `data/levels/` (70MB, 36s, plus a false positive), so it is not a drop-in. Third, `check-added-large-files` does the same thing one layer down — its source intersects the filenames prek hands it with `added_files()` (`git diff --staged --diff-filter=A`), so under `--all-files` it also measures nothing. That one *is* fixable, and is fixed: it carries `args: [--enforce-all]` in the config. **When adding any upstream hook, read its source for a `--staged`/`added_files()` default before trusting its green tick.** One caveat that is *not* about hooks: pr-check.yml's job `name:` is the required-status-check context in the repo ruleset (`bun check`) — renaming the job leaves `main` requiring a check that never reports, so every PR sits pending and unmergeable. Change the ruleset first.

Run a single test: `bun test --test-name-pattern='<name>' tests/game.test.mjs`. There is no build step. Runtime is Bun, not Node — `node:*` built-ins (fs, child_process, url) still work since Bun implements them natively.

**Commit messages and PR titles/bodies are written in English**, always — the history has Chinese ones from before this rule; new ones don't add to them. UI copy and the docs under `docs/` stay Traditional Chinese.

## Architecture

### Runtime (src/)

`main.js` is the only wiring point — game modules never import each other, and there is no event bus. The single data flow is:

```
wheel.js ──gesture ends(word)──▶ game.submit(word) ──result object──▶ main.js dispatches to grid / HUD / pronunciation
```

- [game.js](src/game.js) — all level state and win logic, **pure logic, no DOM** (this is what makes it unit-testable). `submit(word)` returns a discriminated result object (`target` / `bonus` / `duplicate` / `invalid`) — the shape is specified in design doc §10. `createGame` accepts an injectable `rng` (default `Math.random`) so hint-cell selection is deterministic in tests. Economy constants live in the `ECONOMY` object at the top; never scatter coin values elsewhere.
- [wheel.js](src/wheel.js) — letter wheel + pointer gestures. Hit-testing (`hitIndex`), selection (`applyHit`), and shuffle permutation (`permutationAt` + `shuffleStep`, Lehmer-code unranking stepped by a golden-ratio coprime step for a deterministic full cycle back to the initial layout) are exported pure functions for testing. Selection is bound to button *index*, not letter value, because wheels can contain duplicate letters.
- [grid.js](src/grid.js), [dictionary-card.js](src/dictionary-card.js) — DOM rendering only. grid.js takes an injected `isFound` (`game.isFound`) and marks every cell whose target word is complete with `role="button"` + an `aria-label` — that one attribute is a **three-way contract**: it is the press-feedback hook in style.css (`.cell[role]:active`), the VoiceOver button semantics, and the only thing that says "this cell opens the dictionary card" (UI doc §4-E). Swapping it for a class breaks the first two silently, and both only show up on a real device. The `role` must never appear without the `aria-label`: with just the role VoiceOver reads "A, button" — which says nothing about what pressing it does, and the same letter on the wheel reads "A" (wheel letters are `<div>`s, not buttons — they are `pointer-events: none` and never receive their own `click`, so button semantics would promise an interaction that does not exist). grid.js also exports `snapshotText` (emoji grid for the text-only share — board *shape* only, two colors, no progress; share targets tend to drop text when files are attached, so sharing sends no image) and `snapshotBlob` (canvas PNG for the manual download button — the button is currently `hidden` in index.html, code kept for later: board as spoiler-free colored blocks plus the letter wheel; colors read from CSS variables so it follows the theme). dictionary-card.js also owns `speechSynthesis` pronunciation (`speak`/`stopSpeech`), used by both its speaker button and main.js's auto-pronounce on target hit (§6.1). Its iOS unlock rule is **not** the same as the `<audio>` one below — only a `click` wakes the TTS engine (`touchend`/`pointerdown` were both measured failing) and a drag never produces one, re-locking on every page load. That is why index.html opens with the `#gate` tap-to-continue screen: it is the only guaranteed `click` in normal play, so without it a pure-drag player hears no pronunciation for the whole page load, and the lock returns on every reload. It once carried the sfx unlock too; that half is gone with the sfx, this half is not — do not remove the gate as decoration. Design doc §7 has the measurements, don't re-test.
- [redeem.js](src/redeem.js) — redemption-code verification: JWT (alg pinned to ES256) checked with WebCrypto against the `PUBLIC_KEYS` kid→JWK whitelist; single-use tracked by `jti` in the save. A payload may carry a `uid`, which binds the code to one player (`tools/make-code.mjs --uid`); codes without one keep working for everybody. Codes are minted locally with `tools/make-code.mjs` (private keys in gitignored `tools/keys/` — never commit them).
- [storage.js](src/storage.js) — single-key JSON save. `normalizeSave` is pure: any corrupt/unrecognized data resets to a fresh save. Also owns the player id (`newUid`/`isUid`/`normalizeUid`/`formatUid`; make-code.mjs imports `isUid`/`normalizeUid` to validate the id a player reports) — 12 chars of Crockford Base32, 10 random + 2 salted-checksum, backfilled in `loadSave` alongside `firstOpenAt`. The salt ships with the frontend, so the checksum only stops typos and randomly-typed strings; it is not a defence. Design doc §9 has the rationale (and the redemption-code mechanism the `redeem.js`/`make-code.mjs` comments cite), and the invite-code idea it keeps attracting is answered in design doc §16 — a browser has no device id, so nothing offline can tell a friend's device from an incognito window.
- [bridge.js](src/bridge.js) — platform abstraction (save/load/share/copy). **Game code must go through `bridge`, never touch `localStorage` or native APIs directly** — this is the one module that gets swapped for native implementations in Phase 2. It carries only methods with a live caller: the `showAd()`/`buy()` Phase 3 stubs were deleted on 2026-07-29 (zero callers for their whole life, and `buy()`'s bare `Promise.reject()` would have been an unhandled rejection if anything had called it). Design doc §13 keeps the interface *shape* for Phase 3 and records why writing the bodies early bought nothing.
- [strings.js](src/strings.js) — all UI copy in one object. No i18n framework.

[sw.js](sw.js) + [manifest.webmanifest](manifest.webmanifest) at the repo root make it a PWA (design doc §2 for the caching strategy, §16 for why the old "no service worker" call was reversed). The service worker is **stale-while-revalidate for everything, no second rule** — a stale asset self-heals on the next load, which is what makes "forgot to bump `CACHE`" cost one load instead of trapping players on a broken version forever (the revalidate is a plain `fetch`, so GitHub Pages' `max-age=600` delays that heal by up to 10 minutes — design doc §2). Its `SHELL` precache list names every `src/*.js` file: **adding or renaming a module means editing three lists** — the import in `main.js`, `index.html`'s `modulepreload`, and `sw.js`'s `SHELL`. A test in `tests/game.test.mjs` walks `src/` on disk and enforces the latter two against it (it does not parse `main.js`'s imports — an unimported module still has to be listed), because `cache.addAll` is all-or-nothing: one path that 404s — or two that resolve to the same URL, which `addAll`'s single batch rejects with `InvalidStateError` — fails the whole `install`, so the cost of a bad entry is *no offline at all*, reported only in the service worker console. The test covers both: every listed path exists on disk, and no two resolve to the same URL. `SHELL` also carries `assets/licenses.txt` — the license texts have to travel with every copy (design doc §14), offline included. Navigation requests **whose pathname is the scope root** are keyed as `./` on both read and write, so `/?fbclid=…` entry points (tracking params platforms append to shared links) still hit the precached shell offline *and* refresh it (keying writes by full URL would pile up entries that are never read while leaving `./` frozen at install time). The pathname check is not optional — the About section's `assets/licenses.txt` link is also a navigation, and aliasing it to `./` would serve the game HTML instead of the license text *and* overwrite the shell entry with `text/plain`. Root files are published by an explicit `cp` list in `.github/workflows/deploy.yml`: **a new file at the repo root that the site needs must be added there or it simply won't exist in production** — a second test in `tests/game.test.mjs` checks that list against `SHELL`, because the failure is completely silent (`bun run serve` is fine, `register()`'s `.catch()` swallows the 404).

Screens are `<section>` elements toggled with `hidden` in [index.html](index.html) — no router, no history API. Only one interactive overlay may be open at a time (stacking rules in UI doc §4).

### Level data pipeline (tools/)

`data/levels/` is **generated — do not hand-edit it**. Pipeline: `fetch-data` downloads `tools/data/enable1.txt` (bonus dictionary) and `tools/data/ecdict.csv` (Chinese translations), then builds `tools/data/wordinfo.json` (frequency + WordNet English definitions + ECDICT Traditional Chinese translations via OpenCC, via [build-wordinfo.py](tools/build-wordinfo.py) run through `uv`), then [generate-levels.mjs](tools/generate-levels.mjs) picks base words per difficulty band, finds subwords via an alphagram index, backtracks a crossword layout (20 attempts per level, best-scored kept), and embeds each target word's definition. RNG is seeded by level id, so output is fully deterministic and diffable. A built-in validator runs last — any invalid level fails the whole batch. Difficulty curve (3–4 letter wheels for the first 100 levels, ramp to 6 letters by level 300, then mixed bands with occasional easy levels, 500 total) and frequency thresholds live in `BANDS` + `bandFor` in generate-levels.mjs. build-wordinfo.py skips ECDICT `abbr.` senses — abbreviation-only word forms (e.g. "tho") are excluded from target candidates entirely.

Output is one `data/levels/<id>.json` per level plus a `data/levels/index.json` manifest (`{ "count": N }`) — not a single monolithic file. A single `levels.json` embedding every level's English+Chinese definitions grew past 500KB and blocked first paint (`boot()` had to fetch and parse it all before rendering anything). `src/main.js` `boot()` only fetches `index.json`; `startLevel(id)` fetches that level's own file on demand, so first load only pays for the current level (~1–2KB). Two background prefetches warm the HTTP cache so the real fetch hits it: `boot()` fires one for `save.currentLevel` *in parallel with* `index.json` (the saved level id is known without the manifest — awaiting it first would just trade the old waterfall for a new one), and `startLevel` fires one for `id + 1` once the current level is rendered. A third pair repeats both on the service worker's `controllerchange`, because the install trip's fetches bypass the SW entirely (design doc §2). All go through `prefetchLevel`, which reads the response body — a `fetch` left unread gets aborted by Safari and may never reach the cache. Biome's formatter/linter skip `data/levels/` (`biome.json` `files.includes`) since it's generated output with its own diffable layout.

### Testing split (design doc §12)

Only pure logic is auto-tested (`tests/*.test.mjs`): game rules, wheel hit/selection math, save normalization, the player-id round trip (`newUid`/`isUid`/`normalizeUid`/`formatUid` — pinned against a fixed uid fixture, not a fresh `newUid()`, because the checksum is only 10 bits and a random typo case would pass by luck ~1/1024 runs; the consumer is a *different program*, `tools/make-code.mjs`, so breakage otherwise surfaces as "a player can't redeem"), redemption-code verification, the dictionary card's vertical placement (`fitVertically` — the card is `position: fixed`, so an unclamped `top` puts it off-screen where it can be neither scrolled to nor dismissed; the arithmetic is split out from the measuring exactly so it can be pinned here), `bridge.share`'s tri-state return (the one non-pure exception — the test swaps `navigator`/`document` on `globalThis`; its decision table is documented in UI doc §4-D and only misbehaves on a real device), plus a validator pass over `data/levels/` and consistency checks on the two machine-checkable PWA shell lists (`sw.js`'s `SHELL`, `index.html`'s `modulepreload` — see Architecture for why `main.js`'s imports are not one of them) and on `deploy.yml`'s root-file `cp` allowlist, plus a grep of the tracked tree for `.local.*` citations (see the Doc sync map for why). Unit tests use inline fixtures — never assert on `data/levels/` contents, which change on regeneration. UI, animation, and touch feel are manually tested against the §17 acceptance checklist on real devices. Desktop keyboard input in the wheel (letter keys / Backspace / Enter) exists for dev iteration, not for players.

## Doc sync map

Before finishing any change, update the docs that describe what you touched (a Stop hook in `.claude/settings.json` reminds you once per turn). Each fact has one source of truth; the other files named in its row carry only a short summary or pointer that must be kept in sync — never a second full copy:

| You changed | Update |
|---|---|
| Gameplay rules, economy, level algorithm, licensing | design doc section first (source of truth), then CLAUDE.md/README if they summarize it |
| Commands / tools / hooks (package.json, mise.toml, .pre-commit-config.yaml) | CLAUDE.md Commands + README 快速開始 (the `.claude/settings.json` Stop hook does **not** watch `.pre-commit-config.yaml` — nothing will remind you) |
| Module added/renamed/responsibility moved (src/) | CLAUDE.md Architecture + README 專案結構 + index.html `modulepreload` 清單 |
| Generator pipeline (tools/) | CLAUDE.md pipeline section + README 關卡資料 |
| Project status (deployed, phase done) | `.serena/memories/project-overview.md` only |

`.serena/memories/*` must stay a thin pointer to CLAUDE.md plus status deltas — if you're writing architecture there, it belongs in CLAUDE.md instead.

**Never cite a `.local.*` file from a code comment, a doc, or a memory.** `.gitignore` swallows the whole `*.local.*` pattern, so those notes exist on one machine only: a clone gets the reference without the target, and the reasoning behind the code is simply gone. One such note (a redemption-code/feature evaluation) was folded into design doc §9, §15 Phase 1.5-4 and §16 on 2026-07-27, and the five comment references that pointed into it (four `評估文件 §…`, one bare `§3-4`) were repointed at §9. Decisions go in `docs/`; `.local.*` is scratch that nobody else can read. A test in `tests/game.test.mjs` greps the tracked tree for `.local.` citations, because a dangling one fails as silently as a missing `SHELL` entry — the reference still reads fine, it just leads nowhere.

## Constraints worth remembering

- Everything must work fully offline from local files — no runtime network calls, no dictionary/pronunciation APIs, no CDN assets. Pronunciation uses the browser's built-in `speechSynthesis`.
- Data/asset licensing is tracked in design doc §14; the attribution text lives in the About section of index.html, which links to `assets/licenses.txt` — the **full** WordNet and ECDICT license texts, shipped with the site because both licenses require the notice to travel with every copy and `data/levels/*.json` embeds their definitions. Naming the license is not enough, and the link has to point at our own copy, not upstream — linking out ships nothing and breaks the offline rule. Anything whose data ends up in `data/` needs its text in that file (build-time-only tools like OpenCC/NLTK/wordfreq don't). TWL/SOWPODS word lists and the COCA frequency table are prohibited (proprietary/paid).
- Animations should use `transform`/`opacity` only, and respect `prefers-reduced-motion`.
- **There is no in-app "add to home screen" prompt.** One was built and removed on 2026-07-27: intercepting `beforeinstallprompt` requires `preventDefault()`, which suppresses the browser's own install banner in exchange for a button inside a panel nobody opens, and with no analytics the install rate is unmeasurable. Design doc §15 Phase 1.5-4 has the full reasoning, the conditions for revisiting, and where it would go if it comes back (the opening gate, not the settings card); §16 lists it as deliberately not built.
- **There are no sound effects.** Two implementations were built and both lost to iOS audio-session behaviour: `<audio>` elements, whose `play()` blocks the main thread synchronously (191ms idle, 752ms after TTS held the session, 60-109ms when one element is retriggered fast) and caused the dropped frames, the undrawn selection line and the swallowed sfx; and Web Audio, whose `start()` is a clean 0.0ms but whose `AudioContext` will not wake while the iOS mute switch is on — `resume()` measured 3163/5124/8974ms, so the opening seconds were silent anyway. The whole layer is gone, along with the element pool, the per-element unlock loop, the silent warmup and the gate's unlock wait. The only audio left is the TTS pronunciation on a correct word; wrong words shake, bonuses show +N coins and bump the top-bar coin total, level clear shows the card. Design doc §13 has every measurement and the dead ends — read it before proposing sfx again (§16 lists it as deliberately not built).
