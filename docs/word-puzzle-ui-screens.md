# 畫面清單與 UI 流程

> 主設計文件的配套文件（見 [docs/word-puzzle-game-design.md](docs/word-puzzle-game-design.md)），只管「有哪些畫面、長什麼樣、怎麼切換」。UX 原則（回饋動畫、觸控細節）在主文件 §4、§7，此處不重複。

## 1. 畫面清單

整個遊戲只有 **2 個全螢幕畫面 + 5 個 overlay**，外加一層開場閘門（I）。仍然沒有標題畫面——閘門只顯示「Lexoria · 第 N 關 · 點擊繼續」，點掉就是上次進行中的關卡（Wordscapes 同款做法）。閘門存在的理由不是品牌也不是選單，純粹是 iOS Safari 的 TTS 只有 `click` 叫得醒（設計文件 §7），拖曳玩家沒有它就整關聽不到發音（它曾經順帶做 `<audio>` 解鎖，音效整層移除後那半沒了，剩下的 TTS 這半仍然成立——設計文件 §13）。「第 N 關」那行直接讀存檔的 `currentLevel`、不等 `index.json`（省一趟 RTT），而**全破的存檔那個值是 `levelCount+1`、是一個不存在的關**，照寫就變成「第 501 關」點下去卻是全破畫面(G)；所以 `boot()` 拿到關卡數、發現超界時把那行改寫成 `allClear`（「更多關卡即將推出」）。補寫排在 `index.json` 回來之後，這時閘門幾乎必然還蓋著（玩家還沒點），等於不必為了正確的第一印象多付那趟 RTT。

| # | 名稱 | 型態 | 進入方式 |
|---|------|------|---------|
| A | 遊戲主畫面 | 全螢幕 | 開啟預設；從關卡選擇點關卡 |
| B | 關卡選擇 | 全螢幕 | 主畫面點左上關卡編號 |
| C | 過關 | overlay | 找齊全部目標字時自動 |
| D | 設定 | overlay | 主畫面點齒輪 |
| E | 查詞卡片 | popover | 點已找到的目標字格，或點過關卡片(C)的單字鈕 |
| F | 教學 | overlay | 兩段：滑字（第 1 關首次進入，完成第一個字即收）→ 查詞（**每關**找到字後出現在格盤下緣，真的點過一次才永久收） |
| G | 全破 | 全螢幕 | 最後一關過關後的「下一關」 |
| H | 載入失敗 | 全螢幕 | 開啟或換關時關卡資料取不到（斷網/部署中）自動；僅一句訊息＋重新載入按鈕 |
| I | 開場閘門 | 全螢幕 | 每次載入頁面自動（首次進站、重新整理、分頁還原、Phase 2 冷啟動）；點任意處即收，同一次載入不再出現。關卡切換不經過它 |
| — | 橫式遮罩 | overlay | 偵測到橫向時自動 |

**刻意不做的畫面**：標題/主選單、每日獎勵、商店、成就——Phase 3 以後的事（主文件 §16）。

## 2. 畫面 A：遊戲主畫面

```
┌──────────────────────────┐
│ [第42關] 🪙128 [+25] ⚙  │ ← 頂列：關卡鈕(進B)、金幣、定時領取鈕(可領時填實心珊瑚底、凸起陰影加珊瑚外暈並顯示+25——它與左邊的金幣數字同為 .chip.coin，不換底色兩顆長得一樣，玩家看不出這顆能按；冷卻中退回淡底、貼平無陰影（不用 opacity 壓暗——會把倒數文字一起淡到 2.8:1，低於 AA），顯示 h:mm 倒數，仍可點——點了抖動並顯示「X 小時 Y 分後可領取金幣」，避免倒數被誤讀成限時。最後一分鐘改逐秒顯示「59 秒」，此時點擊訊息改「就快好了！」；歸零翻成+25 的瞬間播彈跳動畫，這是玩家守著逐秒倒數在等的收尾，不是招攬。招攬的活全部交給上面的靜態配色：開頁補播彈跳、畫面中央的文字提示、持續跳動，三個都評估過後放棄——辨識問題的根因是兩顆膠囊長得一樣，配色解掉了就不必用動畫補救，而動態各有代價（開頁彈跳跟格盤繪製搶注意力、中央文字打斷解謎視線、持續跳動踩到 WCAG 2.2.2）)、設定鈕(開D)
│                          │
│     ┌─┬─┬─┬─┬─┐         │
│     │P│L│A│N│E│         │
│     └─┼─┴─┴─┴─┘         │ ← 填字格：置中，佔上方約 55% 高
│       │E│                │
│       │A│ ...            │
│                          │
│        ｢ P L A ｣         │ ← 目前拼字串：僅手勢進行中顯示
│                          │
│            （A）          │
│         （P）🔀（E）      │ ← 字母轉盤：下 1/3 拇指區，
│  💡    （L）（N）         │    中央洗牌鈕
│  -25                     │
└──────────────────────────┘
```

- 頂列高度固定，格子區域用剩餘空間置中縮放（格子尺寸 = 可用寬高取小除以行列數，主文件 §7）。
- **整個 `.screen` 收成一欄居中**（`max-width: 480px; margin-inline: auto`）。手機上這條永遠不生效（視窗本來就更窄），它只為桌機／平板：不收邊的話關卡鈕貼最左、齒輪貼最右、中間空一大片，而轉盤封頂 330px、格子封頂 56px，兩者都不會長大去填那片空白——分享連結有相當比例是在桌機點開的，那是第一印象。480 = 轉盤直徑上限 330 + 兩側呼吸空間，再寬轉盤也不會變大。已知代價：欄寬成為寬盤面（9 欄以上）的新瓶頸，桌機上格子比以前小一點，換來的是與手機一致的版面。對 `.hint-btn` 沒有影響（一度以為會把它拉近轉盤，實際量過沒有）：它的 `right` 第一分支跟著轉盤直徑走，在容器寬 > 直徑 + 128px——轉盤封頂時即 458px——就已經贏過保底的 `100% − 56px`，1440px 與 480px 量到的間距同樣是 8px；收窄只是讓保底分支離生效更遠。
- 金幣數字**變多時彈一下**（`.chip.bump`；`main.js updateCoins` 比對前後值）：「+N」閃在畫面中央的拼字串顯示區，金幣數字卻在最上角，是畫面上距離最遠的兩點，不動一下沒有人會把兩者連起來。**只在變多時播**——花掉金幣（提示）不慶祝。實際看得到的是 **bonus 與領取這兩條**：過關與兌換進帳時，蓋滿畫面的 `.overlay`（半透明 + 模糊，§4）已經在頂列上面，彈跳被遮著；但那兩張卡自己就寫著「+10 金幣」「已兌換 N 金幣」——彈跳有資訊量的場合剛好就是它看得見的場合，不必為另外兩條調順序。用 `bump` 不是格子字母的 `pop`：`pop` 從 `scale(0.3)` 起跳，那是**登場**動畫，套在本來就在畫面上的藥丸上會讓整顆先縮成三成再彈回來。只播主畫面那顆：關卡選擇的 `#coin-count-b` 在切走時是 `display: none`，看不到的東西不必動。**沒有 box 的元素一律不播**這件事是 `playOnce` 自己擋的（`getClientRects().length`），不是靠呼叫端挑對元素：加了 class 卻沒有 box，動畫根本不會啟動、`animationend`／`animationcancel` 都不會來，class 會殘留到下次切回畫面才莫名播一次——而主畫面那顆 `#coin-count` 也有輪到被蓋住的時候（倒數在關卡選擇畫面歸零時的 `#btn-claim.pop` 同理），只挑元素擋不完。
- 提示鈕（💡 −25）固定在**左下角**，不是轉盤正左方：圓內接於矩形，剩下的空白全集中在四個角，而水平中線正是圓最寬、整個版面唯一沒有餘裕的那條線——正左方那版在 390×844 上離螢幕邊與轉盤各只剩 4px／2.5px（靠 clamp 硬塞的，原本想留 8px），320×568 更會壓到圓周約 4px。移到轉盤底部那一帶後，圓半寬從 R 降為 √(R²−d²)，橫向就有空間了。**但只有垂直改，水平仍跟著轉盤直徑走**（`right: min(50% + d/2 + 8px, 100% − 56px)`）：轉盤 330px 封頂，桌機上版面再寬轉盤也不會變大，改貼螢幕邊會讓按鈕離轉盤好幾百 px、看起來不屬於轉盤——「左下角」指的是**轉盤的**左下角，不是畫面的。對齊的是轉盤外框左緣而非圓弧切點，因為按鈕底緣與轉盤底緣齊平時最近點是它的右上角，要貼著圓弧得算 √(124R−3844)，跟按鈕高度綁死，用常數逼近會在某個尺寸失手；代價是桌機上最近點離圓弧約 36px（轉盤 330px 封頂時），手機上圓弧本來就在旁邊看不出來。選左下而非右下：按下去就直接扣 25 金幣、沒有確認，不該放在右手拇指的自然靜止弧上。金幣不足時按下 → 鈕抖動並強調價格（主文件 §8），**而且按之前就看得出來**：金幣不足時**燈泡與價格一起**退成 `--text-soft`（`.hint-btn.poor`，`updateCoins` 切換）——同領取鈕那條原則，辨識問題用配色解、不要留到按下去才用動畫補救。一開始只淡價格，實際看下來不夠：那是整顆鈕上最小的一塊字，最搶眼的燈泡還全亮著，讀起來像價格標籤褪色而不是這顆現在按不動。燈泡是 `background-color: currentColor` + mask，所以把顏色下放到按鈕本身它自己會跟；`small` 另有 `--accent-ink`，兩條選擇器都要寫。**只動前景色**，底色／邊框／陰影全部不碰：壓暗整顆鈕看起來像功能壞了，而它只是現在買不起；用 `opacity` 更不行，會把價格數字一起淡到 AA 以下（同 `#btn-claim.cooling` 的教訓）。鈕的可存取名稱是 `hintLabel`（「提示，花費 25 金幣」，由 `main.js` 從 `ECONOMY` 設）而不是寫死的「提示」：`aria-label` 會整個蓋掉鈕上看得見的「−25」，不寫價格的話讀螢幕的人按下去才發現扣了 25，而這是全遊戲唯一不可逆的花費。
- 拼字串顯示區在格子與轉盤之間，平時空白、不佔版面跳動（高度預留固定）。它**刻意不是 `aria-live` 區塊**：`showPreview` 每滑過一個字母就重寫一次，掛上去等於整段拖曳都在逐字播報 C→CA→CAT，把玩家自己的節奏蓋掉。真正該播的只有 `flashPreview` 那幾則結果訊息（已找到／額外單字／金幣不足／無效字／領取金幣），那些另外寫進看不見的 `#status`（`role="status"`，`.sr-only`）。`#status` 跟 `#tap-hint` 一樣放在所有 screen 之外——screen 用 `hidden` 切換，live region 一旦離開無障礙樹，下次寫入就被當成新插入的子樹而不播報（§4-F 第三段有完整理由）。900ms 後兩邊一起清空：不清的話連續兩次相同訊息（連撞兩個「已找到」）文字沒變，輔助技術不會再播第二次。兩邊的字**只有無效字那則不同**（`flashPreview` 的第三個參數）：畫面上那則的「無效」全在抖動動畫裡，字本身就是玩家剛拼的那個字，照抄進 `#status` 等於只唸出剛拼的字、聽不出被判無效——而答對時 TTS 唸的也正是同一個字，兩者會變成同一句。播報那份改用 `notAWord`。

## 3. 畫面 B：關卡選擇

```
┌──────────────────────────┐
│ ← 返回          🪙128    │
│                          │
│  ✓1  ✓2  ✓3  ✓4  ✓5     │
│  ✓6 ...  ▶42  🔒43 🔒44  │ ← 網格列表：✓已完成(可重玩)
│  🔒45 ...                │    ▶目前關 🔒未解鎖
└──────────────────────────┘
```

- 純網格按鈕列表，捲動即可，不需要分頁或章節地圖；進入時自動捲到目前關卡（置中）。
- 重玩已完成關卡：進入時 `levelState` 重新開始，但**不重複**給金幣（主文件 §7）。重玩中離開再回來 → 回到 `currentLevel`，不保存重玩進度（`levelState` 只屬於 `currentLevel`，存檔結構不用改）。「不重複」是字面意思，不是「一毛都沒有」：被扣掉的是過關金幣（`onWin` 的 `!replay`），而重玩時**沒找過**的 bonus 字照樣 +2——`foundBonusWords` 按關卡記錄，同一個字一輩子只給一次，所以沒有刷金幣迴圈。文案因此是「重玩不再**重複**獲得金幣」，少了那兩個字就是假話：玩家會一邊讀到這句、一邊看見頂列金幣變多。
- **重玩時開場在拼字串顯示區閃一次 `replayNote`**（「重玩不再重複獲得金幣」，`startLevel` 尾端呼叫 `flashPreview`）：不講的話，從這裡回頭玩舊關的人要一路破完、看到過關卡片上的**同一句** `replayNote` 才知道，整關都以為在賺。**刻意不在頂列常駐標記**：這是獎勵的事、不是關卡身分的事，而頂列是全畫面唯一會折行的一列（見下一條），不該為一則只在破關那一刻才有後果的訊息花那個位置；`flashPreview` 又順帶把它寫進 `#status`，無障礙那條路白拿。曾經做過的版本是把關卡鈕整串換成 `↺ N`（取代而非附加，正是為了頂列寬度），拿掉的理由是它把全遊戲一致的「第 N 關」句式換成一個字符、還得為符號另外補 `aria-label`，成本都花在版面而不是訊息上。代價是訊息會消失：中途切走再回來的人看不到——可接受，是玩家自己從這個列表點進來的，而過關卡片會再說一次。呼叫要放在 `showScreen('game')` 之後，`#preview` 所在的 screen 還 `hidden` 時 900ms 就走完了。
  - 已知的**既有**問題（不是這次改出來的，也還沒修）：320px 寬（iPhone SE 一代）上，關卡編號進到三位數之後，光是「第 500 關」＋金幣＋冷卻中的「3:59」＋齒輪就已經超過一行，關卡鈕會折成三行、頂列長到 106px。要修得動頂列本身（縮 padding／gap、或關卡鈕換更短的寫法），不是靠這條。

## 4. Overlay 們

**C 過關**：半透明遮罩 + 中央卡片：「過關！ +10 🪙」、本關找到的 bonus 數、本關全部目標字（可點，彈出 E 查詞卡）、［下一關］按鈕、［分享戰績］按鈕（次要樣式；盤面與 D 的［分享］相同，只有第一句不同——這裡報「我破了第 N 關，額外找到 N 個單字」，D 那顆只說「我正在玩第 N 關」，細節見 D）。剛過關是唯一有動機炫耀的時刻，D 那顆則是隨時想到就能邀人，兩種場合不同所以兩邊都放。點卡片外不關閉（過關是單向流程）。**Escape 也不接**，同一條規則——這張卡的出口只有［下一關］。最後一關的［下一關］→ 進畫面 G。列出目標字是為了讓玩家能查完成最後一字時來不及點格子看到的釋義。卡片本身是 `role="dialog" aria-modal="true" aria-labelledby="clear-title" tabindex="-1"`，開啟時 `main.js` 把焦點送進**卡片自己**（不是［下一關］鈕）：過關的慶祝全是視覺的，不這麼做讀螢幕的人完全不知道自己贏了；焦點落在按鈕上只聽得到「下一關，按鈕」，落在卡片上 VoiceOver 才會唸出 `aria-labelledby` 指的「過關！ +10 金幣」。理由與 D 同一套，寫在 D。

**D 設定**：半透明遮罩 + 卡片：發音開關、玩家編號（`XXXX-XXXX-XXXX`，點一下複製、按鈕文字暫時換成「已複製」，複製不到則換成「無法複製，請手動抄下」，1.5 秒還原；回報這串才能拿專屬兌換碼。複製出去的就是鈕上帶分隔線的那串——所見即所得，玩家貼進聊天室才不會以為複製錯了；`make-code.mjs --uid` 的 `normalizeUid` 會剝掉分隔符與大小寫，帶不帶都收）、［分享］按鈕（次要樣式，與旁邊的玩家編號／兌換同一層級——沒有人為了分享才打開設定，它不該是這張卡最搶眼的按鈕；定位是「隨時邀人玩」而非報戰績，所以開頭只說在玩第幾關。純文字：emoji 格盤 + 關卡數 + 字母盤。格盤只畫關卡形狀、不畫進度，進度由關卡數表達；字母隨文案附上讓收到的人能直接在聊天室裡解題（與下載圖同樣的取捨——字母本來就是公開輸入，答案才是雷），並且**排序後**才附上：`wheel.getLetters()` 給的是洗牌後的視覺順序（下載圖要跟畫面對得上才這樣設計），但純文字裡沒有畫面可對，不排序的話同一關分享兩次字母串不同，看起來像亂碼而不是一組字母。字數與方向不必寫進文案：每段長度 ≥2 的連續白格直線即一個字，這條填字慣例足以從盤面推回全部字位（已對 500 關驗證無例外）（⬜ 可填的格／⬛ 背景，沿用填字遊戲「白格可下筆、黑格是牆」的通用慣例而非品牌色；兩者同屬 U+2B1x 區塊以確保每列對齊，理由詳見 `snapshotText` 註解）；桌機手機一律先複製到剪貼簿再開系統分享面板——部分分享目標（Facebook 那類政策上只收連結的）只收連結、丟掉文字，剪貼簿裡通常有完整版可自行貼上——「通常」是因為桌面上分享面板搶走焦點時 `clipboard.writeText` 會被 Chromium 以「Document is not focused」擋掉，而那正好是最需要它成功的情境（取消面板的人就是要自己貼）。所以**面板收掉之後會再補寫一次**，而且要**等焦點真的回到頁面**（`document.hasFocus()`／`focus` 事件，上限 300ms）才寫——「面板關掉」與「`navigator.share` 的 promise settle」沒有規範保證的先後，不等就有機會撞上同一個錯，補寫等於沒補；上限也不能省，手機分享成功會直接切到對方 App，`focus` 永遠不會來，沒有上限的話 `share()` 就永不回傳。第一次就成功的手機不會多寫。兩次都失敗、**而且面板確實有開起來（含使用者取消）**，才是真的沒有保險，那種情況什麼都不提示；面板本身也叫不起來時仍要提示（見下）。**Windows 是唯一要分開處理的平台**：它的分享面板把 `text`／`url` 當 `DataPackage` 上兩個各自獨立的欄位（`SetText`／`SetWebLink`），多數目標只讀 WebLink，整段文案就這樣不見了（「電腦版分享只剩網址」的成因）；所以 Windows 上把網址併進單一 `text` 欄位傳。只挑 Windows 而非全平台改單欄位，是因為 iOS 要有真正的 `NSURL` item 才長得出預覽卡片、也才留得住只吃 URL 的分享目標，而 Android 本來就會把兩者串成一個字串、改不改都一樣。**macOS 不必比照 Windows**（問過一次就記在這，不用再查）：Apple 兩邊共用同一份 `WKShareSheet`，`text` 以 `NSString` 進 array、`url` 以帶 LinkPresentation metadata 的 item 進**同一個** array，接收端是「能收的 item 都收」，不是 Windows 那種「兩個具名欄位挑一個讀」——Mail、訊息那類目標文字與網址都拿得到。macOS 已知的怪癖是 `title` 會被丟掉（Mail 只留 url + text），而我們本來就沒送 `title`，所以踩不到。判斷用 `navigator.userAgentData?.platform`，不是在猜 UA 字串：Windows 上有 `navigator.share` 的只有 Chromium 系（Firefox 桌面版預設沒有 Web Share，走剪貼簿那條；Windows 沒有 Safari）。這個修正有兩個**已知例外，都不另外處理**：（1）Windows 的 Web Share 從 Chrome 81 就有、`userAgentData` 要 Chrome 90 才有，中間那段舊版 Chromium（以及手動打開 `dom.webshare.enabled` 的 Firefox）會 `?.` 短路、落回分開傳，分享出去仍可能只剩網址——就是修正前的行為；（2）Windows 這條不送 `SetWebLink`，只吃 WebLink 的目標（「複製連結」、附近共享那類）會收到空的、或直接不出現在面板上。把 `url` 加回去救不了（2）：那些目標本來就會忽略 `text`，兩個都給等於沒修，所以只能二選一，選了「多數目標拿得到完整文案」。分享失敗時（權限政策擋下、手勢過期、面板叫不起來，`AbortError` 的取消不算）落回剪貼簿的結果去提示，不能當成送出成功——那會讓按鈕看起來完全沒反應。面板關閉或被取消後，只要剪貼簿真的寫成功就**一律**提示「分享內容已複製，貼上就能傳給朋友」：不是每個人的分享目標都在系統面板上——想貼到網頁版聊天室、表單、文件的人按完分享只會看到一排用不到的 App，取消面板正是「我的目標不在上面」那個訊號。提示排在面板之後才閃（`bridge.share` 是 await 完才回傳），所以不會被面板蓋掉、也不會浪費在看不到的時間裡；文案要帶主詞（「**分享內容**已複製」而不是光「已複製」），否則剛分享成功的人會把它讀成分享失敗；主詞用「分享內容」而不是「文案」——後者是行銷／工程的說法，玩家不會這樣稱呼自己剛複製的東西。反過來，剪貼簿沒寫成就什麼都不提示——這句話是承諾，讓人去貼卻貼不出東西比不提示更糟。這也是為什麼不能「先樂觀提示、再開面板」：那個時間點 `writeText` 還沒 settle，而先 await 它就會吃掉手勢、面板根本開不了（見上）；帶檔分享時多數目標也會丟文字，故一律不帶圖）、［下載圖片］按鈕（canvas 快照 PNG 直接下載；目前以 `hidden` 隱藏，程式碼保留備用）、**兌換欄位**（輸入框 +［兌換］鈕 + 一行結果訊息，文案見 §6 的 `redeem*`；這是兌換碼**唯一的入口**，沒有 `?code=` 兌換連結，貼進整串舊網址也照收，機制與理由見主文件 §9）、「關於」（版本號 + 素材授權聲明，主文件 §14 要求的授權頁就放這；末行的「License texts」連到同站的 `assets/licenses.txt`，放 WordNet 與 ECDICT 的條文全文——§14 要求條文隨副本散布，但兩面條文牆不該塞進設定卡，另開檔案兩邊都成立）。點卡片外關閉，**另有右上角［✕］**——遮罩那條路讀螢幕的人走不到（`.overlay` 不可聚焦，VoiceOver 滑動巡覽碰不到它），開了就困在裡面，所以這顆是無障礙的出口而非裝飾。第三條路是 **Escape**，但它跟轉盤的鍵盤輸入一樣只服務開發迭代（§4-E），不能拿來取代［✕］。三條路共用 `closeSettings()`，才不會有一條忘了把焦點還回去——關掉時焦點交還開卡的齒輪鈕，不還的話焦點落回 `body`，讀螢幕的人得從畫面最上面重新滑一次才找得回自己剛才在哪裡。

卡片是 `role="dialog" aria-modal="true" aria-labelledby="settings-title" tabindex="-1"`，開啟時把焦點送進**卡片自己**：`aria-modal` 讓 VoiceOver 的滑動巡覽把卡片外的一切藏起來（沒有它，開著設定卡也能一路滑到底下的轉盤與格盤，聽起來像沒有東西擋著），`tabindex="-1"` 是 `focus()` 的落點，VO 會跟著唸出標題，玩家才知道自己開了什麼——焦點進第一顆按鈕的話只聽得到「關閉」。**刻意沒有做 JS 焦點陷阱**：對觸控輔助技術來說 `aria-modal` 已經等於陷阱，剩下會用 Tab 逃出去的只有桌面鍵盤，而桌面鍵盤在這個專案裡只服務開發迭代，為它寫十幾行 focus trap 不划算。真要補時是加在這裡，不是散到各個按鈕上。同一套（`role`／`aria-modal`／焦點進卡片）也套在 C 過關卡上。卡片超過畫面高度時**自己捲**（`.card` 上 `max-height: 88%` + `overflow-y: auto`，遮罩是 `position: fixed inset: 0`、高度已是定值，用 % 才不會像 vh 那樣跟 iOS 網址列收合對不上）：不設上限的話，展開「關於」的六行授權文字在小螢幕上會被 `align-items: center` 上下裁掉，連遮罩都被推出畫面，只剩兩側各 4vw 的縫可以點，「點卡片外關閉」等於失效。因此 `.card` 是全站第二個 `overflow-y: auto`，要跟 `.level-list` 一樣列進 main.js 那條 `touchmove` 白名單、也一樣要 `overscroll-behavior: none`（主文件 §4 的內嵌 WebView 下拉關閉）。上限與捲動掛在 `.card` 而非只給設定卡：C 過關卡同樣沒有保護。

**分享文案的三條規則**（改 `shareText`／`shareAll` 前先讀，違反其中任一條都會讓訊息讀起來像詐騙轉發）：

1. **邀請指向盤面，不指向網址。** 訊息裡要有一句主詞是「你」的話，而且它談的是已經附在訊息裡的謎題（「能填滿這些 ⬜ 嗎？」）。緊貼網址上方的句子一律會被讀成行動召喚，所以網址前面保持空行、不放任何字。
2. **具體細節就是可信度。** 關卡數、字母、真實盤面是對方能當場驗證的東西，詐騙訊息不會附。不要為了「更吸引人」把它們換成形容詞、驚嘆號或程度副詞，也不要有任何利益承諾（「一起玩送金幣」是最像詐騙的一類，何況沒有後端也發不出去）。
3. **符號當句中圖例。** ⬜ 直接寫進問句、下一行就是同一符號的方陣，對應關係不用解釋。不要退回「填滿空格」（讀者得自己把「空格」對到 ⬜），也不要另加一行 `⬜ = 要填的格`（訊息會變成說明書）。`shareAll` 不適用這條——全破訊息沒有附盤面，沒有符號可指，所以維持「填滿空格」的純描述。

另外：朋友點進網址是從**第 1 關**開始（沒有 deep link，關卡逐關解鎖），所以任何暗示「點進來玩這一關」的句子都是假的，不能寫。

**E 查詞卡片**：貼著被點的格子彈出的小 popover：單字、一句繁中釋義（主）、一句英文釋義（輔）、🔊 喇叭鈕（Web Speech API，主文件 §6）。**四邊都夾在畫面內**：左右往內夾，上下同樣要夾——下方放不下就翻到錨點上方，兩邊都放不下（瀏覽器縮放、大字級）取空間大的那側並讓卡片自己捲（`max-height` + `overflow-y`，所以 `.dict-card` 也在 `main.js` 那份 `touchmove` 放行名單裡，主文件 §4）。只夾左右不夠：釋義最長有 311 字元（WordNet 的 GAS，第 335 關），錨在盤面最後一列往下開整張卡會掉出底部，而卡片是 `position: fixed`——掉出去就既捲不到也點不到，只能重開一關。夾邊界的算式抽成 `fitVertically` 釘在單元測試裡（主文件 §12），量測與寫樣式留在 `show()`。點卡片外任意處關閉，桌面鍵盤另有 Escape（疊層最上面那張先關，所以 C + E 都開著時 Escape 只收 E）。**彈出時節點會被搬進當下那張 `aria-modal="true"` 的 dialog 裡**（`anchorEl.closest('[aria-modal="true"]')`，沒有就掛回 `body`）：卡片本體平常是 `body` 的直接子節點，而 `aria-modal` 會讓輔助技術把 dialog 以外的一切藏起來——C + E 這個組合（C 的單字鈕正是 E 最主要的入口，因為完成最後一字時根本來不及點格子）在不搬的情況下，讀螢幕的人點得下去、卡片也真的畫出來了，卻永遠滑不到釋義與喇叭鈕。`position: fixed` 不吃 DOM 位置，版面與定位計算都不變，所以搬家只影響無障礙樹。無英文語音可用時隱藏喇叭鈕；喇叭鈕的 `aria-label` 是 `strings.speakLabel`（「唸出 {字}」），跟其餘標籤一樣走 strings.js——寫死英文的話讀螢幕的人會在一整頁繁中裡聽到中英夾雜。兩個入口——格盤上已找到的字、過關卡片(C)的單字鈕——共用同一段程式（`openDict`），但**只有格盤那條算「玩家已經知道格子可以點」**、收掉 F 第二段（單字鈕本來就長得像按鈕，教不了格盤，完整理由在 F 第二段「為什麼 C 的單字鈕不算」）。**已找到的字**的格子按下去會縮一下（同 `.clear-word-chip` 手感）：這只是點下去之後的確認，教不了「可以點」，發現性靠 F 第二段。條件是「所屬目標字已找到」而不是「格子有字」——提示只揭示一格、整字還沒補滿時那格點了沒反應，給它按壓回饋（與 VoiceOver 的 button 語意）就是騙人。實作上由 `grid.js` 在 `createGrid` 與每次 `update()` 給這些格子掛上 `role="button"`（一關內只增不減、換關整個格盤重建，所以不必拿掉），CSS（`.cell[role]:active`）與 VoiceOver 讀同一個標記。**`role` 一定要配 `aria-label`**（`strings.cellDictLabel`，內容是「查看 {字} 的解釋」）：只有 `role` 的話 VoiceOver 唸出來是「A，按鈕」——除了字母本身什麼都沒說，按下去會發生什麼完全聽不出來，而轉盤上同一個字母唸的是「A」，兩者只差一個「按鈕」，分不出這顆是查解釋還是拼字母。刻意**不給 `tabindex`／Enter 處理**：整場沒有鍵盤玩法（轉盤是拖曳手勢），VoiceOver 觸控巡覽不靠 `tabindex` 也到得了；要補鍵盤就得整個格盤做 roving tabindex，那是另一件事，不是這個 `role` 的附帶義務。

**對照組：轉盤的字母是 `<div>` 不是 `<button>`**（`wheel.js`）。命中判斷走座標（`hitIndex`），那些節點是 `pointer-events: none`，從來收不到自己的 `click`——掛成 `button` 只會讓 VoiceOver 唸出「A，按鈕」再雙點一下毫無反應，而且它們會全部排進 Tab 順序。用 `div` 仍然唸得出字母（玩家聽得到這關有哪些字母，資訊沒有少），只是不再假裝可以按。轉盤本身對輔助技術仍然是玩不了的（拖曳手勢），這只是不再給出假的可按承諾，不是把它變成無障礙的。

**F 教學**：兩段文案、**各自一個節點**（`#overlay-tutorial`／`#tap-hint`，共用 `.tutorial` 樣式），都不攔截操作（`pointer-events: none`），存檔各記一個旗標在 `settings` 裡。共用一個節點試過：兩段的位置、生命週期、完成旗標全都不同，狀態得在過關、換關、點開查詞、換畫面四處手動同步，漏一處就殘留（例如過關卡片背後透出上一關座標的殘影）。

1. **滑字**（`tutorial`／`tutorialDone`）：第 1 關疊在轉盤上的手指軌跡動畫 + 一句文案——玩家照著滑或自己亂滑都行，完成第一個字即永久收掉。
2. **查詞**（`tapWordHint`／`dictHintDone`，2026-07-25 試玩補丁）：**每關**找到目標字後出現——**拼出來的和被提示補滿的都算**（條件是「格盤上有字可以點了」，不是「拼出來的」；花金幣卡關的人反而更想知道那個字的意思）。位置貼著**格盤下緣**（JS 量 `.grid` 的 rect 寫進 `top`，大盤面填滿 `.grid-area` 時夾在區域下緣，寧可疊在最後一列上也不要壓到預覽列；夾的距離用元素自己的高度而不是寫死 px，放大字型才不會壓下去）。夾住的那種情形一定會疊到最後一列——`--cell` 由 `cqh` 決定時格盤高度剛好等於容器內容框，沒有空隙可以躲——所以這句有**實心膠囊底**（`width: fit-content`）：純 text-shadow 蓋不住底下的粗體字母。小盤面時膠囊只包住文字，看起來仍是一句浮字。量出來的是視窗座標，所以 `resize`（轉向、iOS 網址列收合）時還開著就重量一次。**過關時要收掉**——過關卡片是半透明模糊背景，留著會透出殘影，按「下一關」後還會停在上一關格盤的座標上蓋著載入畫面；過關後改由 C 的單字鈕承接。設定 overlay 開著時同樣不能透出來，但那是**暫時**讓路，不能真的收掉（收了這一關就再也看不到），所以交給 CSS：`body:has(.overlay:not([hidden])) #tap-hint` 設 `opacity: 0`，overlay 收掉就自己回來。選擇器只挑 `#tap-hint`、不寫共用的 `.tutorial`——第 1 段要不要一起讓路沒人決定過，順手一起改掉會變成沒人記得的行為差異。開場閘門(I) 不靠 CSS 藏：閘門蓋著時 `showTapHint()` 直接不寫入（下一段），沒有東西需要藏。

   **開場閘門(I) 蓋著時不寫入**：`aria-live` 一寫就播報，續玩已有找到字的關卡必經這條路——不擋的話 VoiceOver 會在玩家還停在「點擊繼續」、格盤還被閘門蓋著點不到的時候就唸出這句，而文字沒變不會再播第二次，等於整場只播在最沒用的那一刻。所以 `showTapHint()` 自己檢查閘門，閘門的 click 收掉閘門後補叫一次。同理，出不出現的判斷（旗標、已經開著、格盤上有沒有字可以點）全部在 `showTapHint()` 裡，呼叫點一律無條件呼叫——四個入口（進關卡、拼出字、提示補滿字、收閘門）各判一次遲早漏一個。

   這個節點**沒有 `hidden`**：它是 `aria-live` 區塊，一旦離開無障礙樹（`hidden`／`display: none`），下次寫入會被當成「新插入的子樹」而不是既有 live region 的變更，多數輔助技術不播報——而這句提示存在的理由就是「沒人自己發現得了」。所以節點常駐，開關一律走**文字空／不空**（`main.js hideTapHint`），收起來的樣子由 `#tap-hint:empty` 把 padding／底色／脈動關掉。同理，讓路用 `opacity` 而不是 `display`。

   三件事都是試玩逼出來的，改動前先讀完：
   - **為什麼要有**：沒有人自己發現得了「點格子可以查詞」。已填的格子長得像浮起的字磚，那是裝飾感不是可點感；靜態樣式在手機上講不出「可以點」。
   - **為什麼不跟滑字教學同位置**：兩段疊在轉盤上方同一格，會被當成同一句話直接忽略；而且這句講的是格盤，把眼睛帶去看轉盤等於白講。
   - **為什麼不改成自動彈卡示範**：評估過「第一次拼出字就自動彈查詞卡」——彈出來只證明卡片存在，不會讓人推論出「是我點得出來的」，而且一輩子一次，沒點的人到第二關照樣不知道。
   - **收在哪**：真的在**格盤上**點過一次才永久收（`openDict(word, entry, anchorEl, learned)` 只有 `onCellTap` 傳 `true`）。不用計時、不用計次——沒點過就是沒學會，換關再講一次不算煩。
   - **為什麼 C 的單字鈕不算**（2026-07-26 修正，原本兩者都算）：單字鈕本來就是 `<button>`、長得就像按鈕，點它學到的是「這些膠囊可以點」，推不出「格盤上的字磚也可以點」——而後者正是「為什麼要有」那條。何況完成最後一個字時過關卡片馬上蓋上來，玩家根本沒機會在格子上點，第一次接觸查詞卡幾乎必然是從單字鈕：兩者算同一件事的話，相當比例的玩家會在從沒點過格子的情況下永久失去提示。代價是已經會了的人多看一兩次那句話，比「沒學會的人再也看不到」便宜。

   `ponytail:` 從沒點過的人會每關都看到這句，沒有次數上限。真有人嫌煩再加計數，不要現在猜一個數字。

   舊玩家因為 `dictHintDone` 是新欄位（`normalizeSave` 補預設 `false`）同樣看得到。

**G 全破**：全螢幕「更多關卡即將推出」+ 返回關卡選擇按鈕（可重玩舊關）+［分享戰績］按鈕（次要樣式）。這裡分享的是「破完目前所有關卡」而非某一盤——進到 G 時 `game`/`wheel` 還停在最後一關，秀那張盤面沒有意義；也刻意不寫關卡總數（同 `shareAll`）。

**橫式遮罩**：全螢幕不透明「請轉直畫面」，蓋過其他一切。條件是 `(orientation: landscape) and (max-height: 500px) and (pointer: coarse)`——**`pointer: coarse` 不是保險條款而是必要條件**：桌機把視窗拉矮（或筆電開半螢幕）就同時滿足前兩項，整個遊戲會被遮罩蓋掉，而桌機使用者轉不了螢幕。`coarse` 讀的是**主要**輸入裝置，所以帶觸控螢幕的筆電（主要輸入仍是觸控板）不會誤中，平板橫著拿仍然會中——那正是要蓋的情況。

### 疊層順序（z-index 由上到下）

```
橫式遮罩 > 開場閘門(I) > 查詞卡(E) > 過關(C)/全破(G) > 設定(D) > 教學(F) > 遊戲主畫面
```

閘門(I) 排在橫式遮罩之下：橫著開頁時該先看到「請轉直畫面」。

同時只會出現一個可互動 overlay，唯一例外是 E：E 可疊在 C 之上（點過關卡片列出的目標字彈出），因為 C 是單向流程、不會被 E 誤觸關閉。開 D 前仍先關 E；C 觸發時只重置舊的 E（避免錨點指向已消失的格子），不強制關閉、C 內可再點字重新彈出。教學(F)不攔截操作所以不算互動層。

## 5. 導覽流程

```
（開啟）→ A 遊戲主畫面 ⇄ B 關卡選擇
              │ 找齊目標字
              ▼
           C 過關 ──下一關──▶ A（下一關）
              └─（最後一關）──▶ G 全破 ──▶ B
```

- 沒有瀏覽器返回鍵整合：Phase 1 是單頁 Web，不動 history API；Capacitor 包殼後再處理 Android 返回鍵（B→A、overlay→關閉）。
- 畫面切換 = 顯示/隱藏全螢幕 `<section>`（A/B/G/H 四個，同時只有一個可見），不做路由。載入失敗 H 也走同一個切換函式，換關重試成功才收得掉。

## 7. 色票草案（主文件 §19-3 的拍板素材）

給一版可以直接開工的預設值；視覺定案時只改這組變數，元件不動。
只做深色一套（主文件 §19-3）——不跟隨 `prefers-color-scheme`，不做淺色主題：

```css
:root {
  color-scheme: dark;
  --bg: #10201f;            /* 深青墨黑底 */
  --surface: #1b2c2b;       /* 卡片/轉盤底 */
  --grid-empty: #2a3b39;    /* 未填格 */
  --grid-filled: #1c8f88;   /* 已填格底（filled 與 revealed 同色，主文件 §10）*/
  --letter-on-fill: #ffffff;
  --text: #e6ede9;
  --accent: #ff7a52;        /* 亮珊瑚：金幣、強調、選中字母 */
  --wheel-line: #ff7a52;    /* 手勢連線 */
}
```

- 已填格的青墨底白字（大字粗體）對比 ≥ 3:1，達 WCAG AA-large；完整定案色票（含陰影、次要文字等）在 `src/style.css` 的 `:root`。
- §4-D 的分享格盤刻意**不**跟這組變數走（用 ⬜／⬛ 的填字遊戲慣例色）——它要在別人的聊天室裡成立，跟著品牌色反而會在淺色背景失效。改色票時不用管它。
- 標題字體：系統字型堆疊（`system-ui`）先開工，品牌字體是視覺定案的事，不擋路。
